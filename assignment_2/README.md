## 1. Overview & Research Objectives

This study investigates two central research questions in high-performance numerical computing:
1. **Part A (Dense Optimisation):** How do microarchitectural cache-oriented algorithmic transformations (specifically **loop reordering to $i\text{-}k\text{-}j$** and **cache tiling/blocking**) mitigate memory latency and improve throughput compared to the canonical $i\text{-}j\text{-}k$ baseline on Apple Silicon (M2)?
2. **Part B (Sparse Matrices):** Under which matrix dimensions $n$ and sparsity thresholds $\rho$ does a **Compressed Sparse Row (CSR)** representation achieve a performance and memory advantage over dense multiplication, accounting for index lookup and output non-zero expansion overhead?

## 4. Key Empirical Findings

### Part A: Dense Optimisation Speedup
- **Stride-1 Cache Locality:** Loop reordering from $i\text{-}j\text{-}k$ to $i\text{-}k\text{-}j$ transforms column-stride accesses on matrix $B$ into contiguous memory access, allowing the Apple Clang compiler to auto-vectorize inner loops using ARM64 NEON SIMD instructions (`fmla.2d`).
- **The DRAM Latency Cliff:** At $n = 2048$, working memory ($100.66\text{ MB}$) overflows the 16 MB L2 cache into external DRAM. While the baseline suffers catastrophic cache thrashing ($30.90\text{ s}$), loop reordering finishes in just **$1.38\text{ s}$**, achieving a **$22.40\times$ speedup**.
- Cache blocking ($B=64$) delivers an **$18.03\times$ speedup** at $n = 2048$.

### Part B: Sparse CSR & Break-Even Crossover
- **The Fill-in Dilemma:** Multiplying two sparse matrices $C = A \times B$ generates non-zero accumulation. At $\rho = 50\%$ and $70\%$, the output matrix $C$ is **$100\%$ dense**, expanding non-zeros by up to $19.87\times$ at $\rho = 95\%$.
- **Crossover Point ($\rho^*$):** Because of pointer indirection, branch mispredictions, and non-zero fill-in, CSR SpGEMM is slower than dense reordered multiplication below $\rho \approx 75\%$.
- **High-Sparsity Acceleration:** Above $\rho = 80\%$, CSR decisively wins, reaching **$51.96\times$ speedup** at $\rho = 99\%$ and **$15,925\times$ speedup** at $\rho = 99.9\%$, while reducing storage footprint by up to **$99.6\%$**.
